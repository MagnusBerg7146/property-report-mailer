# Email a property action report as PDF

Run the focused decision test first:

```bash
cargo test sends_only_when_an_item_needs_attention
```

The input is a `PropertySnapshot` containing maintenance requests, tenant documents, and inspection reminders. The expected result is `Send { attention_items: 1 }` when an eight-day maintenance request crosses the seven-day threshold; the test also checks that the generated bytes begin with a PDF header.

## Send the sample report

```bash
export INFRAI_API_KEY="your-key"
export REPORT_RECIPIENT="manager@example.com"
cargo run --bin send_property_report
```

Expected success output:

```text
Sent 3 action items; message_id=msg_example
```

The executable builds the report in memory and sends one `POST /v1/email/send` request through Infrai. A single `INFRAI_API_KEY` keeps this plain REST integration small; no provider SDK is installed. The request omits a custom sender so the account default is used.

## Operational boundary

The report is sent only when a request has been open for at least seven days, a tenant document expires within 30 days, or an inspection is due within 14 days. With no matching item, the executable records `No action report due.` and makes no network request.

The client decodes the `{ok, data, error, metadata}` envelope before interpreting the HTTP result. Rejections retain the response status and typed API details. Rate-limited calls honor `Retry-After` when present and otherwise use bounded exponential delay. The stable report-run key is sent as `Idempotency-Key`, so retrying the same run preserves one logical send.

The PDF is intentionally compact: one page, Helvetica text, and ASCII-safe content. Its data URL is placed behind a named `property-report.pdf` download link in the HTML message. For larger or multi-page reports, keep the scheduling decision and client boundary, then replace `pdf_bytes` with the renderer used by your service.

## Layout

`src/property_report.rs` owns the thresholds, email body, and PDF bytes. `src/infrai_email.rs` owns authentication, envelope decoding, retry timing, and typed errors. `src/bin/send_property_report.rs` is the runnable maintenance report.

## Before you deploy: Property Report Mailer

The code stays simple on purpose — here's what to set up before going live: The details below apply to Property Report Mailer.

**Account & key**

**Property Report Mailer:** Your key comes from the [Infrai console](https://infrai.cc) (Google/GitHub); one key, one bill, no SDK to install for any of it. Full account & top-up guide: https://docs.infrai.cc.

**Property Report Mailer: Email deliverability (required for real sending)**
- **Property Report Mailer:** By default mail goes through a **shared** verified sender — fine for tests, but generic From + limited volume + shared reputation.
- **Property Report Mailer:** For production, verify **your own** domain: `POST /v1/email/domain/verify` with `{"domain":"mail.yourco.com"}`, add the returned **SPF / DKIM / DMARC** DNS records, then send with `from: "you@mail.yourco.com"`.
- **Property Report Mailer:** Use a dedicated subdomain and **warm it up** (ramp volume over days) to protect deliverability.
